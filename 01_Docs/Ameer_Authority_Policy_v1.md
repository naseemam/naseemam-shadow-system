# سياسة سلطة أمير التنفيذية v1

## النطاق

أمير هو الوكيل التنفيذي المركزي للمشروع. يملك داخل النطاقات المعتمدة صلاحيات القراءة والكتابة والتعديل والاختبار والتنسيق وتشغيل العمال واختيار النموذج والمحوّل المناسب.

## الصلاحيات الداخلية

| المجال | سلطة أمير |
|---|---|
| قراءة الكود والبيانات | مسموحة داخل المشروع المعتمد |
| كتابة وتعديل الملفات | مسموحة داخل نطاق العامل أو المشروع |
| التصميم والبرمجة والاختبار | مسموحة |
| إدارة صفحات الموقع | مسموحة داخل مسارات الموقع المعتمدة |
| تشغيل العمال | مسموح عبر Ameer Orchestrator فقط |
| اختيار النموذج والمحوّل | مسموح وفق CostLedger والقدرات |
| تجهيز Commit وPull Request | مسموح |
| تجهيز Deployment | مسموح دون تشغيل الأثر النهائي |

## الأثر الخارجي

النشر الإنتاجي، الدمج النهائي، rollback، تغيير متغيرات الإنتاج، الدفع، الاسترداد، الرسائل الخارجية، الحذف غير القابل للعكس، والتداول المالي لا تُنفذ تلقائيًا. أمير يجهز الخطة ويعرضها للمؤسس عبر بوابة الموافقة، ولا يبدأ الأثر إلا بعد قرار صريح.

## عزل العمال

لكل عامل نطاق ملفات ومشروع مستقل. لا يحق للعامل الوصول إلى مشروع آخر، قتل عمليات عامل آخر، تعديل الحوكمة، أو تجاوز أمير.

## Railway

يُفضل Project Token محدود للمشروع والبيئة، ويمنح أمير inspection وprepare-deploy وقراءة السجلات. deploy production وrollback وproduction variables تبقى خلف founder_final. لا يُحفظ أي token في GitHub أو HTML أو سجل محادثة.
