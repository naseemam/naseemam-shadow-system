# Cost Tracking in Ameer

يحتفظ أمير بسجل مركزي لاستهلاك واجهة النماذج في جدول `api_usage` داخل `api_cost_ledger.sqlite3`. يسجل كل حدث `task_id` و`run_id` و`agent_id` و`provider` و`model` وعدد رموز الإدخال والإخراج والإجمالي وزمن الاستجابة والحالة.

لا تُحفظ prompts أو مفاتيح API أو ترويسات Authorization في السجل. تأتي أعداد الرموز من حقل `usage` الذي يعيده المزوّد.

## التكلفة المالية

لا يفترض أمير أسعارًا من عنده. لحساب `estimated_cost_usd` يجب ضبط متغير البيئة `AMEER_MODEL_PRICING_JSON` في بيئة التشغيل، مثل:

```json
{
  "model-name": {
    "input_per_1m": 0.0,
    "output_per_1m": 0.0
  }
}
```

تُملأ القيم من جدول التسعير الرسمي للمزوّد المستخدم. وإذا لم يُضبط المتغير، تبقى الرموز مسجلة وتكون حالة التسعير `unpriced` بدل إنتاج رقم مالي غير موثوق.

## المسارات

```text
GET /costs/health
GET /costs/summary
GET /costs/usage?agent_id=engineering&task_id=<task_id>&limit=100
```

`/costs/summary` يعرض الإجماليات والتجميع حسب العامل. ` /costs/usage` يعرض أحداث الاستخدام المرتبطة بالمهمة والتشغيل، دون prompts أو أسرار.

## التوجيه الاقتصادي

يستطيع أمير استخدام عدد الرموز والتكلفة المقدرة والسرعة والحالة كإشارات لتوجيه المهمة إلى أقل نموذج يحقق الجودة المطلوبة. لا يجوز تغيير النموذج لمجرد أنه أرخص إذا لم توجد إشارة جودة أو سياسة واضحة تسمح بذلك.
