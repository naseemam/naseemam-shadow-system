# Execution Plan

## Purpose

Build Ameer as a real executive agent that performs work end-to-end instead of delegating execution back to the Founder.

## Operating Principle

Default flow:

1. Understand context and objective.
2. Retrieve relevant memory/resources.
3. Plan internally.
4. Execute with real tools.
5. Verify results.
6. Repair/retry automatically when needed.
7. Record evidence and continue.

Founder approval appears only for the sovereign gates defined in `06_Code/kernel/ameer_authority.py`.

## Priorities

### 1. Real Execution
- File/document/spreadsheet/media creation.
- Repository and code management.
- Existing site/program/system administration.
- Railway/Cloudflare/GitHub operations.
- VPS/local/VS Code execution.
- Database/connectors/credentials management.

### 2. Worker and Skill Autonomy
- Ameer creates, removes, reassigns and supervises workers according to task needs.
- Ameer may add/update/test/replace skills without a Founder approval loop.
- Workers are execution resources under Ameer orchestration.

### 3. Provider Independence
- Ameer Core owns identity, context, memory, personality and orchestration.
- Model/provider adapters are replaceable.
- Provider changes must not change Ameer.

### 4. School and Business Workspaces
- Generate and manage school records, student tracking, classroom management, worksheets, reports and achievement-portfolio artifacts.
- Generate documents and print-ready outputs directly.
- Operate existing business websites, booking, inventory, staff and project systems.

### 5. Observability Without Blocking
- Record execution evidence and errors.
- Missing access/credentials are technical blockers.
- Audit/telemetry must not become human approval gates.

## Sovereign Founder Approval

Only:
- ownership transfer;
- creation of a new independent site/program/repository/system;
- final production activation of a newly-created root asset;
- final domain transfer that changes control/ownership;
- new external financial commitment or actual external funds movement.

Delegated trading inside the authorized trading account is exempt from per-trade approval.

## Success Criteria

- Routine operations execute without confirmation loops.
- Ameer does not claim execution without evidence.
- Existing assets can be repaired, changed, deployed and administered autonomously.
- Workers/skills/providers can be managed by Ameer.
- Only the central sovereign policy can create a Founder approval request.
