## 1. الهدف

تنفيذ طبقة استمرارية البيانات في بيئة الإنتاج (Railway) بحيث تبقى جميع ملفات الحالة في مجلد `.ameer/` حية بعد كل عملية إعادة نشر.

---

## 2. الملفات المعدَّلة

| الملف | نوع التعديل | الوصف |
|---|---|---|
| `ameer_runtime.py` | إضافة دالة | `resolve_data_root()` — تقرأ `AMEER_DATA_DIR` وتعيد مسار الجذر المناسب |
| `ameer_server.py` | تعديل طفيف | استيراد `resolve_data_root` واستخدامه لتعيين `ROOT` |
| `railway.toml` | إضافة توثيق | تعليمات تهيئة الـ Persistent Volume وربطه بـ `/app/.ameer` |

---

## 3. الإعدادات المضافة

### متغير البيئة المطلوب

```
AMEER_DATA_DIR=/app/.ameer
```

يُضاف في لوحة تحكم Railway → Variables.

### إعداد Persistent Volume (Railway Dashboard)

1. انتقل إلى: **Service → Volumes → Add Volume**
2. اختر حجم مناسب (يكفي 1 GB للبداية).
3. اضبط **Mount Path** على: `/app/.ameer`
4. أضف المتغير: `AMEER_DATA_DIR=/app/.ameer`
5. أعد النشر — يبدأ سريان التخزين الدائم فورًا.

---

## 4. كيف يعمل التصميم

```
AMEER_DATA_DIR=/app/.ameer
        │
        ▼
resolve_data_root()          ← ameer_runtime.py
  → returns Path("/app")     ← (parent of .ameer)
        │
        ▼
ROOT = "/app"               ← ameer_server.py
        │
        ├── KERNEL(workspace_root="/app")
        │     └── state_manager → /app/.ameer/state.json        ✅ على الـ volume
        │     └── decision_engine → /app/.ameer/decisions.json  ✅
        │     └── approval_gate → /app/.ameer/approvals.json    ✅
        │     └── feedback_engine → /app/.ameer/feedback_log.json ✅
        │     └── learning_engine → /app/.ameer/learned_preferences.json ✅
        │                        → /app/.ameer/learning_log.json ✅
        └── ameer_server → /app/.ameer/projects.json            ✅
                        → /app/.ameer/plans.json                ✅
```

- عند غياب `AMEER_DATA_DIR` يُعيد النظام مسار مجلد المستودع تلقائيًا (السلوك الأصلي — التوافق الخلفي مكفول).
- لم يتغير أي منطق في Executive Brain أو Memory أو Governance أو أي واجهة API.

## 6. نتائج التحقق

| الاختبار | النتيجة |
|---|---|
| `resolve_data_root()` بدون `AMEER_DATA_DIR` تعيد `WORKSPACE_ROOT` | ✅ |
| `resolve_data_root()` مع `AMEER_DATA_DIR=/app/.ameer` تعيد `Path("/app")` | ✅ |
| `resolve_data_root()` مع `AMEER_DATA_DIR=/data` (مجلد مختلف) تعيد `Path("/data")` | ✅ |
| لا تغيير على منطق Executive Brain أو Memory أو Governance | ✅ |
| لا تغيير على واجهات الـ API | ✅ |
| التوافق الخلفي (بيئة التطوير المحلية) محفوظ | ✅ |

## 7. المخاطر والقيود المتبقية

| المخاطر | التفاصيل |
|---|---|
| الإعداد يدوي في لوحة Railway | حاليًا لا يوجد IaC رسمي لـ Railway volumes؛ يجب ضبطه يدويًا من لوحة التحكم. |
| النسخ الاحتياطية | Railway Volumes لا يوفر backup تلقائيًا في الخطة المجانية؛ يُنصح بتصدير دوري للبيانات. |
| الأمان | محتوى `.ameer/` يتضمن بيانات حساسة؛ تأكد من أن الـ Volume غير مشارك مع خدمات أخرى. |
| التهيئة الأولى | عند أول نشر مع Volume فارغ، يُنشئ النظام الملفات تلقائيًا من القيم الافتراضية — هذا سلوك صحيح. |

تم تنفيذ P0.4 بنجاح. النظام الآن قادر على الاستمرار بعد كل إعادة نشر على Railway بمجرد:
